## 1. Original problem statement

> "IT Ticket Resolution Suggestion Engine (AI + NLP-Based Support Assistant).
> Design and develop a full-stack IT support ticket resolution system that uses a hybrid NLP approach to suggest solutions to users based on historical support tickets.
> The system should use TF-IDF and Cosine Similarity from Scikit-Learn to identify the most relevant historical tickets and their resolutions. These matches should then be passed to the Groq API using the LLaMA 3.1 8B model, which will generate exactly five synthesized, actionable resolution points for the user's issue.
> The application should have a Streamlit frontend, a FastAPI backend, and a database using PostgreSQL (NeonDB) or local SQLite through SQLAlchemy.
> The system should support database seeding with approximately 50 synthetic historical tickets and resolutions to enable the NLP engine to identify relevant matches.
> The application should be runnable locally, with the FastAPI backend exposing autogenerated API documentation through /docs and the Streamlit frontend providing the user interface."

### Key constraints from the problem statement

- Exactly **five** actionable resolution steps must be returned on success.
- **TF-IDF + cosine similarity** from Scikit-learn are mandatory.
- **Groq API** with a LLaMA model is mandatory.
- **~50 synthetic historical tickets** must seed the database.
- FastAPI `/docs` endpoint must be available.
- SQLite is the initial database; PostgreSQL/NeonDB is an optional upgrade.

## 2. What the product actually does

A user submits a plain-English IT issue. Ticker:

1. Converts the historical ticket corpus into TF-IDF vectors (in memory).
2. Converts the user's issue into the same vector space.
3. Computes cosine similarity to rank the most relevant historical tickets.
4. Passes the top relevant tickets and their resolutions to the Groq LLM.
5. Validates that the LLM returned exactly five actionable steps.
6. Returns those steps, the matched tickets (with similarity scores), and generation status.

This is a **RAG-style pipeline using lexical retrieval** (not semantic vector search or embeddings).

## 6. API contract summary

### POST /resolve — primary endpoint

**Request:**
```json
{
  "issue_description": "string (1–2000 chars)"
}
```

**Success response (HTTP 200):**
```json
{
  "issue_description": "...",
  "resolution_steps": ["Step 1...", "Step 2...", "Step 3...", "Step 4...", "Step 5..."],
  "matched_tickets": [
    {
      "ticket_id": 1,
      "title": "...",
      "category": "...",
      "similarity_score": 0.42
    }
  ],
  "generation_status": "success",
  "message": null
}
```

**`generation_status` values:**

| Value                | Meaning                                                       |
|----------------------|---------------------------------------------------------------|
| `success`            | Five steps generated and validated                            |
| `insufficient_evidence` | No tickets met the similarity threshold; LLM not called    |
| `generation_error`   | Groq API failed or response format could not be validated     |

Full schema in `docs/architecture/API_CONTRACT.md`.

## 12. Known defects and limitations

- TF-IDF is lexical: it cannot match conceptually identical issues described with different vocabulary. This is documented as expected behaviour, not a bug.
- `llama-3.1-8b-instant` is deprecated. The current recommended model is set in `GROQ_MODEL`. Verify before first live use.
- SQLite has no connection pooling; not suitable for concurrent production load. Acceptable for a hackathon demo.

## 13. Launch commands

```bash
# 1. Activate virtual environment
.venv\Scripts\Activate.ps1          # Windows PowerShell
source .venv/bin/activate            # macOS / Linux

# 2. Install dependencies
pip install -r requirements.txt

# 3. Seed the database
python -m app.db.seed

# 4. Start the backend (terminal 1)
uvicorn app.main:app --reload --port 8000

# 5. Start the frontend (terminal 2)
streamlit run frontend/streamlit_app.py

# 6. Run tests
pytest tests/ -v
```
